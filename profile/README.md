<h2>一、搭建前要准备什么</h2>
<p>三样东西：一台海外服务器、一条可用的住宅线路或静态住宅地址、一套能登录后台的账号环境，缺一样都跑不起来。</p>
<p>服务器不用太强，两核两G足够跑代理和浏览器，真正吃资源的是同时打开的浏览器窗口数量。</p>
<p>系统建议用常见的Linux发行版，文档多、排错快；Windows也能做，但远程桌面加浏览器的内存占用会高不少。</p>
<h2>二、系统与网络初始化</h2>
<p>装完系统先更新源、开好防火墙，只放行需要的端口，SSH改掉默认端口并禁用密码登录，这几步别省。</p>
<p>再看路由表，确认默认网关正确、没有残留的旧路由，多地址环境里路由表乱是最常见的故障来源。</p>
<h3>网卡与地址绑定</h3>
<p>住宅地址如果是通过上游设备给的，用DHCP或静态配置都行，配完用ip addr确认地址真的挂上了。</p>
<p>不要让两块网卡抢同一个网段，出现来回跳的情况，排查很费时间，配置时直接写死网关更稳。</p>

<h2>三、把住宅IP接到服务器</h2>
<p>最省事的做法是让住宅侧设备拨号，服务器通过内网或隧道把流量送过去，出口地址就是那条宽带。</p>
<p>如果服务商直接给静态地址，把地址配到服务器网卡上更直接，少一层转发，延迟和故障点都更少。</p>
<p>代理隧道方式部署最快，一条命令就能通，代价是多一次加解密，带宽高的时候CPU会成为瓶颈。</p>
<h2>四、分流与端口映射</h2>
<p>多地址场景要按源地址或按端口分流，前者适合给每个业务固定出口，后者适合客户端按端口选线路。</p>
<p>用策略路由时记得配规则优先级，默认路由放最后，否则规则互相覆盖，表现是时通时不通。</p>
<h3>端口规划</h3>
<p>给每个业务分配一段端口，写进文档，新同事照着配不会错，出问题也能从端口反推是哪条线路。</p>
<p>对外只暴露必要端口，其余用内网访问，公网暴露越多，被扫描和尝试登录的概率越高。</p>
<h2>五、浏览器环境怎么放</h2>
<p>服务器上装浏览器只用于集中管理，实际操作建议通过远程桌面或指纹浏览器客户端接入，各人环境互不影响。</p>
<p>每个店铺一个配置文件，代理指向对应端口，配置文件名和台账一致，交接时不用再问谁对应哪个店。</p>
<p>多人共用一台服务器时，注意错开高峰，浏览器窗口同时开太多，内存吃满会拖慢所有人。</p>
<h2>六、稳定性检查清单</h2>
<p>检查四项：地址是否固定、重连是否回原址、晚高峰是否掉速、日志是否有异常断连，四项都过再交付使用。</p>
<p>建议写一个定时脚本，每十分钟记录一次出口地址和延迟，出问题时直接看曲线，比回忆当时情况可靠。</p>
<h3>日志至少留七天</h3>
<p>日志保留一周，覆盖一个完整业务周期，遇到间歇性故障时有据可查，也能看出问题是否集中在某个时段。</p>

<h2>常见问答</h2>
<h3>一定要用服务器吗？</h3>
<p>答：不一定。单人单店用本机加代理即可。服务器主要解决多人共用、地址集中管理、长期在线这三个需求。</p>
<h3>服务器放在哪个地区好？</h3>
<p>答：放在离住宅线路近的地区，转发跳数少、延迟低。实际选择要看你采购的住宅地址在哪个国家。</p>
<h3>住宅线路断了会自动切换吗？</h3>
<p>答：默认不会。需要自己配健康检查和备用线路，切换逻辑要提前设计，否则断线后所有店铺一起掉。</p>
<h3>这套环境能保证店铺稳定吗？</h3>
<p>答：不能。网络环境只是其中一个变量，账号资料、经营行为、平台规则都会影响结果，任何方案都不构成保证。</p>
